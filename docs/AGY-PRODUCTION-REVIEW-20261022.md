Remove absolute privacy/security guarantees and unsupported statistics. Audit Features and DownloadSection for similar claims.
- **P1 — Simulated preview is presented like measured transport.** `apps/landing/src/components/ShowcaseWindow.tsx:49`: hardcoded Mesh WebRTC: 14ms. Reproduce on any connection/offline. Reproduce on narrow viewport by opening the hamburger and inspecting the accessibility tree. Remove hiding from the ancestor; make only the scrim decorative. ## Verified runtime results — frozen production snapshot

Built an independent snapshot outside `apps/landing` with Vite; snapshot TypeScript check passes. AGY's dev server and dist directory were not used or overwritten. Results: `output/production-review-20261022/landing-results.json`; full-page screenshots: `screenshots/landing-<width>.png` in that directory.

- All requested widths **320, 360, 375, 390, 430, 600, 768, 800, 1024, 1280, 1366, 1440, 1920, 2560**, plus **900 and 1100**, pass the document overflow check and element bounding-box check. Full-page screenshots were captured for every width. Mobile is a long stacked page; at 768–800 the three-column feature/architecture cards become cramped. Prefer a two-column or stacked layout until the cards have adequate reading width. This is a P2 visual-quality issue, not an overflow failure.
- **P2 — Navigation wraps at intermediate desktop widths.** `apps/landing/src/landing.css` header/nav breakpoint rules. Reproduce at **900 and 1024px** (`screenshots/landing-900.png`, `landing-1024.png`): Voice Rooms, Screen Sharing, Windows App and Sign In wrap into two lines inside the shallow header. Keep the drawer breakpoint until the full single-row navigation fits (roughly 1100px for this content), or simplify the top-level destinations. This is visible in full-page screenshots despite passing overflow checks.
- Real Chromium page zoom at **125%, 150%, 200%** (Electron `webContents.setZoomFactor`, 1280px content window) gives **1024, 853, 640 CSS px** respectively and passes the document overflow checks. Menu opens at 150% and 200%. `zoom-results.json` and `screenshots/zoom-*.png` record the evidence. This is actual browser-engine zoom, not CSS `zoom` or device-scale emulation; physical browser chrome shortcuts were not tested.
- Mobile menu opens under synthesized touchscreen tap. Escape closes it. The dialog is hidden from accessibility APIs by the ancestor `aria-hidden=true`, focus initially stays on the trigger, and focus is not restored to the trigger after closing from inside the menu. P1 remains confirmed. The in-app browser accessibility tree reproduces the missing navigation links while the menu is visibly open.
- The reaction control toggles **4 → 5 → 4**. Mute changes its icon but exposes no `aria-pressed`; add an accessible toggle state and changing label. P2: `ShowcaseWindow.tsx` mute/deafen controls. Audit reaction selected states too.
- Mobile has **16 visible targets smaller than 44px in at least one dimension**, including preview controls and footer links; desktop has 35. Provide 44px touch hit areas where practical, particularly drawer close/preview controls. Small inline links are not automatically a WCAG failure; evaluate spacing and actual use. P2.
- Reduced-motion emulation succeeds: zero running animations, every main section remains visible, and scroll behavior becomes auto. Preserve this functional behavior. Replace the global 0.01ms duration override with explicit component alternatives when adding richer motion.
- No JavaScript console errors, page errors or failed requests were observed during the suite. The deterministic Impeccable source scan returns `[]`; it does not detect the verified runtime menu/claim problems.
- Snapshot build: **261.58kB JS / 76.48kB gzip; 26.27kB CSS / 5.15kB gzip**. No extra animation dependency. At idle there are seven repeating animations, 370 DOM nodes and approximately 29MB sampled JS heap; those are one local observation, not a CPU/memory-leak benchmark. Resource timing used a warm cache and must not be used as a production speed claim.
- **P2 — Font/icon dependency:** `apps/landing/index.html:28` and following loads four text font families plus the broad Material Symbols font from Google, although package font dependencies exist. Prefer subset/self-hosted WOFF2 for used weights and local SVG icons; preload only the critical heading/body face. Test font-blocked/offline fallback. No site-wide zero-third-party-network claim is justified by this implementation.
- **P2 — Oversized branding images:** `apps/landing/public/haven_newlogo.png` is **652,766 bytes**, and `haven-mark.png` is **167,348 bytes**, while displayed logo/rail marks are small. Preserve the approved design but supply appropriately sized optimized transparent images with dimensions and responsive density variants. The product viewport JPG is already only 29,906 bytes; prioritize the logo rather than degrading that image.
- **P1 — More unsupported sample/performance content:** `Features.tsx` renders `<20ms P2P`, `60 FPS 1080p RAW` and `<1% CPU IDLE`; `Footer.tsx` renders `All systems operational (Supabase + WebRTC mesh)` without a status integration. Remove hardcoded operational/performance assurances. The screenshot itself is a demonstration, so even realistic metrics must not imply current measurement.
