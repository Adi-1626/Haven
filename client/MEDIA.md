# Media hook

`useMedia(socket: Socket | null, currentUserId: string, reportError: (message: string) => void)` manages voice, screen capture, playback, and cleanup. Import it from `./media`.

- `join(channelId): Promise<void>`, `leave(): void`, `voiceChannelId: string | null`.
- `peers: { socketId, user, stream: MediaStream | null, state: { muted, deafened, sharing, speaking? }, volume: number, connectionState? }[]`. Streams contain incoming audio and screen video. The hook creates audio elements itself; UI video elements should be muted to avoid duplicate playback.
- `localStream`, `screenStream`, `muted`, `deafened`, `sharing`, `toggleMute()`, `toggleDeafen()`, `startShare(): Promise<void>`, `stopShare()`.
- `shareOptions: { label, height: number | 'native', width: number }[]`, `setShareQuality(height: number | 'native', fps: 15 | 30 | 60, bitrateMbps: number): Promise<void>`, `quality` contains native/source and configured dimensions, fps, bitrate, and actual outbound/inbound statistics.
- `settings`, `setSettings(partialOrUpdater)`, `devices: MediaDeviceInfo[]`, `enumerateDevices(): Promise<void>`. Settings are `inputDevice`, `outputDevice`, `noiseSuppression`, `echoCancellation`, `pushToTalk`, `inputVolume` (0–2, default 1), and `inputSensitivity` (-60 to -10 dB, default -45), persisted locally under `haven.media.settings`.
- `speaking` is measured from microphone waveform RMS after configured gain and compression. A gate applies the sensitivity threshold, 4 dB hysteresis and 500 ms hangover to preserve pauses within speech. Muting, deafening or releasing Push to Talk immediately suppresses both transmission and activity. Activity emits `voice:activity` only on transitions; peers receive those transitions in `peer.state.speaking`. Soundboard playback is mixed after the microphone gate.
- `connectionStatus` is `disconnected`, `connecting`, `connected` or `reconnecting`. Voice state belongs to the hook rather than a selected text view. Socket reconnect attempts the prior room with fresh capture and peer connections; explicit leave clears reconnect intent.
- `micTest: { status: 'idle' | 'starting' | 'running' | 'error', level: number, speaking: boolean, error: string | null }`, `startMicTest(): Promise<void>`, `stopMicTest(): void`. The test acquires a separate microphone capture only after the user starts it. It uses the same capture constraints and WebAudio gain, compressor and gate as voice, routed exclusively to an isolated playback stream at 30% monitoring volume and the selected output device. Test audio never connects to the voice uplink. Voice mute and Push to Talk do not gate the separate test. Input/processing changes restart the test safely; output changes reroute its audio; gain and sensitivity apply live. A browser without output routing reports a test error for non-default outputs. Use headphones to minimize acoustic feedback.
- `<MicrophoneTest media={media} />` supplies the test controls, level meter, gain and sensitivity controls. Unmounting the component stops the test, including capture that resolves after permission was canceled. Stopping a test releases its own source, graph, output tracks and AudioContext while leaving an active voice capture untouched. Hook/account disposal also stops the test.
- `setPeerVolume(socketId, volume)` uses a range of 0–1. `playSound(url): Promise<void>` mixes decoded audio into the local voice uplink, and monitors it locally unless deafened. Server `sound:play` events only monitor sounds when outside voice; inside voice sound travels through the sender's mixer to prevent duplicate playback.

Screen capture uses the platform `getDisplayMedia` picker (Electron can implement that picker through its session display-media request handler). Capture keeps the source at native dimensions with `resizeMode: 'none'`, and each sender independently downscales to the selected target. Source size changes are detected during the one-second statistics sample using a muted video's intrinsic frame dimensions, falling back to track settings. This handles capture sources whose reported settings lag actual resized frames. Quality options and sender scaling follow those changes. Sender scaling is always at least one, so shrinking sources are never upscaled. `quality.stats` reports measured samples; configured targets are not claims about achieved frame rate or resolution.

Socket events: join acknowledgements have `{ peers: [{ socketId, user, muted, deafened, sharing, speaking }] }`; signaling uses `voice:signal` with `target` on send and `from` on receive. The hook listens for `voice:peer-joined`, `voice:peer-left`, `voice:state`, `voice:activity`, `voice:disconnect`, `sound:play`, `disconnect`, and `connect`. Forced `voice:disconnect` stops capture and playback immediately, clears reconnect intent, and reports the reason. The hook fetches authenticated ICE configuration from `/api/rtc`.

Existing room members initiate each new peer's first offer. This avoids simultaneous initial offers canceling Chrome's initial ICE gathering during automatic rollback. Later changes use perfect negotiation. Signaling is serialized per peer, with bounded buffering for messages that arrive before join acknowledgement creates the peer. Remote video tracks are removed from the presentation stream when sharing stops or the track becomes muted, and restored when live sharing resumes; voice playback continues independently.
