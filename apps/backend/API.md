# API contract

JSON requests/responses, except multipart uploads. Cookie session required except register/login, health, config and invite preview. Errors `{error:string}` with 400/401/403/404/409/410/429. All ids are strings, timestamps epoch milliseconds. Types in `shared/types.ts`. No seed accounts or messages.

- `POST /api/auth/register {username,password,displayName?}`, `POST /api/auth/login {username,password}` → `{user}` and session cookie. `POST /api/auth/logout`, `GET /api/auth/me` → `{user}`.
- `GET /api/bootstrap` → Bootstrap, including `blocked:string[]` (accounts blocked by the current user). User records include both incoming and outgoing friend request participants even when they are offline. `PATCH /api/users/me {displayName?,bio?,avatar?,status?,settings?}` → `{user}`. Public avatar is an emoji or HTTPS URL.
- `POST /api/servers {name,icon?,description?}` → `{server,channel}`. `PATCH /api/servers/:id {name?,icon?,description?}` owner/admin; `DELETE /api/servers/:id` owner only. Names are 1–80 characters, description up to 1,000. Icons accept an HTTPS image URL, emoji or this server's uploaded image URL. `POST /api/servers/:id/icon` owner/admin multipart `file` accepts a static PNG/JPEG/GIF/WebP up to 1 MiB and 1,024×1,024; returns `{server}` with versioned `/api/servers/:id/icon?v=...`. `GET` requires membership. Replacing/removing an uploaded icon cleans up its stored file.
- `GET /api/servers/:id/members` → `{members:[{user,role,serverMuted,serverDeafened}]}`. `PATCH /api/servers/:id/members/:userId {role:'admin'|'member'}` owner only; `DELETE` owner/admin kick, self leave except owner. `POST /api/servers/:id/members/:userId/voice {action:'mute'|'deafen'|'disconnect',enabled?:boolean}` owner/admin; enabled defaults true and false restores mute/deafen. Owners cannot be targeted, admins cannot target other admins, and self-moderation is rejected. Forced mute/deafen flags persist per membership across reconnect/restart. Disconnect ends the current session, without removing membership or banning rejoin.
- `GET /api/servers/:id/emojis` members → `{emojis:ServerEmoji[]}`; bootstrap includes all membership-accessible `serverEmojis`. Owner/admin `POST /api/servers/:id/emojis` multipart `name,file,staticFile?` → `{emoji}`. Names use 2–32 ASCII letters/numbers/underscores, case-insensitively unique per server. Each server supports up to 50 emojis; each upload/preview is at most 256 KiB and 128×128. PNG/APNG, GIF, JPEG and WebP containers are header/structure-validated, with 120 animation-frame maximum and bounded frame rectangles; files are not transcoded or fully decoded by the server. Animated images require a matching-dimension static PNG preview. SVG/HTML are rejected.
- Owner/admin `PATCH /api/emojis/:id {name}` → `{emoji}`, `DELETE /api/emojis/:id` removes image/preview files. Stable tokens `:hvn_UUID:` survive renaming; posts/edits/reactions may only use existing custom emojis belonging to the message channel's server, not DMs or other servers. Reactions allow up to 64 characters. `GET /api/emojis/:id/image` and `/static` require current membership, have private revalidation caching and return 403 after membership removal or 404 after deletion. Clients should render unknown/deleted tokens as text and use static previews for reduced motion/background gaming mode.
- `POST /api/servers/:id/invites {expiresInHours?:number|null}` → `{code,expiresAt}`. Owner/admin only; default expiry 168 hours (7 days), accepted range 1–720 hours; null creates a permanent invite. Existing installation invites remain permanent. `GET /api/servers/:id/invites` owner/admin → `{invites:[{code,createdAt,expiresAt,revokedAt}]}`. `DELETE /api/invites/:code` owner/admin revokes immediately and idempotently.
- `GET /api/invites/:code` public → `{community:{name,icon},expiresAt}`; contains no membership, private channel or account details. Invalid/revoked invites return 404; expired invites return 410. Preview does not join a community. `POST /api/invites/:code/join` authenticated → `{serverId}`; repeat redemption is safe and preserves existing roles.
- `POST /api/servers/:id/channels {name,type,topic?}` → `{channel}`. `PATCH /api/channels/:id {name?,topic?,position?}` → `{channel}`; `DELETE /api/channels/:id`. Admin/owner required.
- `GET /api/messages?channelId=...` or `conversationId=...`, optional `before` timestamp, `limit` (1–100), `q` text → `{messages,hasMore}` chronological order. `POST /api/messages {channelId?|conversationId?,content,replyTo?,attachmentIds?}` → `{message}`.
- `PATCH /api/messages/:id {content}` author only → `{message}`. `DELETE /api/messages/:id` author or server moderator. `POST /api/messages/:id/reactions {emoji}` toggles reaction → `{message}`.
- `POST /api/attachments` multipart `file` plus `channelId` OR `conversationId` (scope fields before file recommended) → `{attachment}`. Max 25 MB. `GET /api/attachments/:id` streams only to scope members.
- `POST /api/friends/requests {username}` → `{request}`. Usernames are case-insensitive, trim whitespace and accept an optional leading `@`; display names are not identifiers. Self request 400, missing username 404, duplicate/existing friendship 409. Reciprocal pending requests return 409 and direct the user to accept the incoming request. `POST /api/friends/requests/:id/accept` recipient only, atomically establishes both friendship directions; `DELETE /api/friends/requests/:id` sender/recipient reject/cancel; `DELETE /api/friends/:userId` removes both friendship directions. Both accounts receive sync. Database insertion triggers and transactions prevent duplicate unordered request pairs without deleting legacy records during migration.
- `POST /api/users/:id/block` atomically records a persistent block and removes friendships/pending requests in both directions; self block 400. `DELETE /api/users/:id/block` removes only the caller's block and does not recreate friendships. Either direction of blocking denies friend requests, new shared conversations, direct-message posts and edits, direct-conversation renames, attachments, reactions and typing. Existing direct-message history remains readable and users may still delete their own messages; existing community and group conversations remain shared spaces and can still receive messages. Blocking does not remove community memberships or end shared voice sessions.
- `POST /api/conversations {memberIds:string[],name?}` → `{conversation}`. Existing 1:1 reused. Maximum 10 participants. Must be friends to invite. `PATCH /api/conversations/:id {name}`; `DELETE /api/conversations/:id/members/me` leaves group.
- `GET /api/servers/:id/sounds` → `{sounds}`. `POST /api/servers/:id/sounds` multipart `name`, `file` (audio ≤5 MB) → `{sound}`. `DELETE /api/sounds/:id` uploader/moderator.
- `GET /api/rtc` → `{iceServers}` from `ICE_SERVERS_JSON`; default Google STUN. Production internet/NAT coverage requires your own authenticated TURN configuration.
- `GET /api/health` → `{ok:true}`.
- `GET /api/config` public → `{publicUrl?:string}`. This is the configured backend public origin for share links; absence means the client must use its current origin and warn about local-only addresses. Connecting to this backend and redeeming a community invite are separate operations. No server reachability is inferred from request headers.

Socket.IO cookie auth. Client listens `sync` to refresh bootstrap; `message` Message for newly created messages; `message:update` Message for edits/reactions (no new unread notification); `message:delete` `{id,channelId,conversationId}`; `typing` `{scope,userId}`; `presence` `{userId,status}`. Emit `typing` `{channelId?|conversationId?}`. All socket emissions accept optional ack `{ok:true}` or `{error}`.

Public profile changes emit `user:update User` (never private settings) to the user's own clients, shared community/conversation members, friends and pending request participants. The server also refreshes all active voice profile snapshots before emitting sync, so joining peers and bootstrap cannot restore an old avatar. Settings-only writes synchronize only the account's own clients and do not broadcast presence or force other users to reload.

Voice: emit `voice:join {channelId,streamProtocol?,signaling?,session?,resume?,entrySound?}` ack `{peers:VoicePeer[],moderation,capabilities:{streamSubscriptions,voiceSessions,entrySounds}}`; `voice:leave`; receive `voice:peer-joined VoicePeer & {resumed,entrySound}`, `voice:peer-left {socketId,reason}` with `reason` one of `leave`, `moved`, `disconnect`, `replaced`, `removed`. Rejoining the same room is idempotent and preserves participant states. `session` is a private per-client key (16–64 characters) that is never sent to other users: a later join by the same account presenting the same key retires that account's stale socket immediately (`reason:'replaced'`, and the stale socket is disconnected) instead of waiting for the heartbeat. `resume:true` marks a reconnection; peers announce it as `resumed`. With `entrySound:true` and no `resume`, the server plays the account's configured entry sound for that community once (`sound:play` with `entry:true`) and announces `entrySound:true`; older clients play it themselves. `signaling:2` advertises support for `reset` signals. Emit `voice:signal {target,description?,candidate?,reset?}` receive `{from,description?,candidate?,reset?}`; `reset:true` asks the receiver to replace its connection with the sender, who then offers. Signaling only within same authorized voice room. Signals are acknowledged; signaling has its own budget, independent of other socket events: 600 burst/8 per second per socket, 150 burst/2 per second per target and 30 burst/0.5 per second for descriptions per target, rejected with `Voice signaling rate exceeded`. The Socket.IO heartbeat is 10 s with a 10 s timeout, so a connection that vanished without closing leaves voice within about 20 s. Maximum 8 connections/room, one voice room per socket. Emit `voice:state {muted,deafened,sharing}`; broadcasts to authorized community members include `{socketId,channelId,muted,deafened,sharing,speaking}`. Emit `voice:activity {speaking:boolean}`; broadcasts `{socketId,channelId,speaking}` to authorized community members, including sidebar observers, only on state changes; no bootstrap sync occurs. Muted/deafened users cannot advertise speaking. Activity is limited separately to 240 events/minute/socket and clients should send only speaking transitions. Emit `sound:play {soundId}`; receive `{sound,userId,entry?}`; every participant, including the sender, plays it locally (it is not mixed into voice). Bootstrap voice roster includes speaking and authorized server rooms only. These use browser WebRTC mesh and require TURN for restrictive NAT; no SFU scalability is claimed.

On forced removal, receive `voice:disconnect {reason}` and close all local voice peer connections/tracks immediately. The server also broadcasts `voice:peer-left` to remaining peers, which must close their connection to that peer. On socket disconnect, close local voice connections too.

Voice join acknowledgements additionally include `moderation:{serverId,muted,deafened}`. `VoicePeer`/`voice:state` include `serverMuted` and `serverDeafened`; effective muted/deafened state combines these persistent flags with the client's requested state. The target account receives `voice:moderated {serverId,muted,deafened}` so only a matching active community applies the flags. Clients must suppress local microphone/output when appropriate and receiving clients must reject audio from server-muted/deafened peers. Forced disconnect uses `reason:'moderator-disconnected'`. This is client-enforced policy over peer-to-peer transport, not an SFU packet filter; modified malicious endpoints cannot be guaranteed to honor policy outside Haven's supported clients.

## Runtime configuration

`PORT` defaults to 3001; `HOST` defaults to 127.0.0.1; `DATA_DIR` defaults to `./data`. `ALLOWED_ORIGINS` is a comma-separated exact-origin list (development defaults http://localhost:5173,http://127.0.0.1:5173). Same-host origins are accepted automatically. `ICE_SERVERS_JSON` accepts an array of browser RTCIceServer configurations, including authenticated TURN credentials. Its value is intentionally sent to signed-in clients and should contain only short-lived TURN credentials for production.

`PUBLIC_URL` optionally specifies the HTTPS origin used by shareable invitations, for example `https://haven.example`. HTTP is accepted only for localhost, 127.0.0.1 or [::1] local testing. Paths, queries, fragments and embedded credentials are rejected at startup. A public URL must actually route to this backend and serve the frontend; this setting does not provide DNS, TLS, firewall access or WebRTC TURN connectivity. For LAN microphone/capture testing, use trusted HTTPS; an HTTP LAN IP is not a secure browser context.

For a single trusted HTTPS reverse proxy, keep the API bound to loopback, set `TRUST_PROXY=1` to recognize proxy protocol/IP headers, and set `SECURE_COOKIES=1` to require HTTPS session cookies. Do not expose the API directly with proxy trust enabled. The normal `server/index.ts` entry loads an existing `.env`; shell/service variables take precedence. Calling `createApp` directly does not load `.env`. `.env.example` is a reference to copy, not an active configuration.

Uploads have a separate per-account limit of 20 files/minute; attachment limit 25 MB; sound limit 5 MB. Other limits: 300 API requests/minute and 300 socket events/minute (excluding `voice:signal` and `voice:activity`, which have their own budgets); 60 new messages/minute; 30 typing events/minute; 10 sound plays/minute. Register/login IP limits are 20/40 attempts per hour. Password derivation uses asynchronous scrypt. SQLite WAL is intended for one local API process; production multi-instance deployment and large voice rooms require a separate datastore/event fabric and SFU.
